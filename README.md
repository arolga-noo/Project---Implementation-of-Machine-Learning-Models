# Внедрение модели прогнозирования дефолта по кредитным картам

## 📌 Описание проекта и его целей
**Цель проекта:** Разработка, контейнеризация и подготовка к промышленной эксплуатации веб-сервиса машинного обучения для оценки кредитных рисков в реальном времени (Online Scoring). 

Сервис анализирует демографические показатели и историю платежей клиента, прогнозируя вероятность дефолта по кредитной карте в следующем месяце.
*   **Бизнес-контекст:** Снижение финансовых потерь банка от невозврата средств за счет точечной фильтрации высокорисковых заявок (вердикт `Reject`).
*   **Датасет:** Default of Credit Card Clients Dataset (UCI Machine Learning Repository).
*   **Модель:** Пайплайн логистической регрессии (`LogisticRegression`) со сквозным масштабированием признаков (`StandardScaler`).

## 🏗️ Архитектура проекта

Проект реализован в виде модульной структуры, разделяющей этапы подготовки данных, обучения модели, развёртывания веб-сервиса и оркестрации инфраструктуры:

```text
├── app/                        # Исходный код веб-сервиса (API)
│   ├── api.py                  # Главный скрипт Flask-приложения, эндпоинты /health и /predict
│   └── model_handler.py        # Модуль загрузки пайплайна и инференса модели
├── data/                       # Локальное хранилище данных (исторический датасет CSV)
├── docker/                     # Конфигурация контейнеризации
│   └── Dockerfile              # Рецепт сборки изолированного Docker-образа веб-сервиса
├── models/                     # Артефакты машинного обучения
│   ├── train_model.py          # Скрипт автоматического обучения логистической регрессии по сети
│   └── model_v1.pkl            # Бинарный файл сохраненных весов обученного пайплайна (артефакт)
├── ARCHITECTURE.md             # Детальное техническое описание системного дизайна проекта
├── README.md                   # Главная документация проекта и инструкции по запуску
├── ab_tests_plan.md            # Методология проведения A/B-тестирования и бизнес-метрики
├── docker-compose.yml          # Файл мультиконтейнерной оркестрации контура (Flask + Nginx)
├── nginx.conf                  # Конфигурация прокси-сервера Nginx и JSON-формата логов
└── requirements.txt            # Список зафиксированных зависимостей Python-окружения
```

### 🧱 Назначение ключевых компонентов:
* **Инференс (app/):** Изолированный веб-сервис принимает пакетные JSON-запросы клиентов, налету масштабирует признаки и выдает скоринговый вердикт (Approve/Reject).
* **Контейнеризация (docker/):** Dockerfile собирает самодостаточную среду на базе `python:3.10-slim`, фиксируя воспроизводимость всех библиотек.
* **Оркестрация (docker-compose.yml):** Объединяет Flask-сервис и обратный прокси Nginx в единую изолированную сеть, настраивая мапинг портов и автоматическое сохранение структурированных логов на жесткий диск.

## 🛠️ Инструкция по запуску

### Вариант 1. Локальный запуск (в изолированном окружении)
1. Склонируйте репозиторий и перейдите в его корень:
   ```bash
   git clone https://github.com
   cd Project---Implementation-of-Machine-Learning-Models
   ```
2. Создайте и активируйте виртуальное окружение `venv`:
   * **Для Linux / macOS / Git Bash:**
     ```bash
     python3 -m venv venv
     source venv/bin/activate
     ```
   * **Для Windows (PowerShell):**
     ```powershell
     python -m venv venv
     .\venv\Scripts\Activate.ps1
     ```
3. Установите зафиксированные зависимости проекта:
   ```bash
   pip install -r requirements.txt
   ```
4. Обучите модель (скрипт скачает датасет с GitHub и создаст файл `models/model_v1.pkl`):
   ```bash
   python models/train_model.py
   ```
5. Запустите Flask веб-сервис:
   ```bash
   python app/api.py
   ```
Приложение станет доступно по адресу: `http://localhost:5000`

### Вариант 2. Запуск в Docker-контейнере
1. Соберите Docker-образ из корня репозитория:
   ```bash
   docker build -f docker/Dockerfile -t credit-card-ml-service:v1.0 .
   ```
2. Запустите изолированный контейнер:
   ```bash
   docker run -d -p 5000:5000 --name credit_app_container credit-card-ml-service:v1.0
   ```

### Вариант 3. Промышленный запуск через Docker Compose (с Nginx)
Разверните весь контур (Flask-сервис + прокси-сервер Nginx для логирования трафика) одной командой:
```bash
docker-compose up -d
```
В этом режиме сервис будет доступен на стандартном веб-порту `80`: `http://localhost/`

### 2. Пакетный инференс модели (POST /predict)
Принимает массив словарей с признаками клиентов в ключе `"features"`. Поддерживает батч-скоринг.

    ```bash

    -H "Content-Type: application/json" \
    -d '{"features": [{"LIMIT_BAL": 50000, "SEX": 1, "EDUCATION": 1, "MARRIAGE": 2, "AGE": 37, "PAY_0": 2, "PAY_2": 2, "PAY_3": 0, "PAY_4": 0, "PAY_5": 0, "PAY_6": 0, "BILL_AMT1": 46990, "BILL_AMT2": 48233, "BILL_AMT3": 49291, "BILL_AMT4": 28314, "BILL_AMT5": 28959, "BILL_AMT6": 29547, "PAY_AMT1": 0, "PAY_AMT2": 2000, "PAY_AMT3": 1200, "PAY_AMT4": 1100, "PAY_AMT5": 1069, "PAY_AMT6": 1000}]}'
    ```
*   **Формат ответа (JSON, Status 200):**
    ```json
    {
      "results": [
        {
          "default_probability": 0.6841,
          "prediction": 1,
          "verdict": "Reject (High Risk)"

MLflow — Отслеживание экспериментовНазначение: Логирование параметров обучения, метрик качества и кода экспериментов.В контексте модели: При каждом запуске скрипта train_model.py [v2] утилита MLflow автоматически записывает в единый реестр гиперпараметры (коэффициент регуляризации C, тип солвера lbfgs), метрики качества (Accuracy, Recall, F1-score) и сохраняет саму модель как артефакт.Ценность: Позволяет визуально сравнивать десятки итераций обучения разных моделей (например, Logistic Regression против Random Forest) через графический интерфейс, выбирать лучший пайплайн по бизнес-метрикам и регистрировать его для последующего деплоя в Docker [v2].

Бизнес-метрики проектаТехнические метрики (Precision, Recall) важны для инженера, но для руководства банка критичны финансовые показатели. На основе выходов модели логистической регрессии рассчитываются две ключевые бизнес-метрики:1. Снижение ожидаемых финансовых потерь (Expected Loss Reduction)Суть: Метрика оценивает, сколько денег банк спасет от дефолта благодаря внедрению модели.Как рассчитать на основе выходов модели:Каждому клиенту, которому модель выдала прогноз prediction = 1 (дефолт) [v1], банк автоматически присылает вердикт Reject (High Risk) [v1] — то есть отказывает в выдаче кредитного лимита. Расчет спасенных средств выглядит так:\(\text{Спасенные\ средства}=\sum _{i\in \text{Reject}}(\text{LIMIT\_BAL}_{i}\times \text{default\_probability}_{i})\)Где LIMIT_BAL — запрашиваемый клиентом кредитный лимит, а default_probability — точная вероятность дефолта, рассчитанная методом predict_proba [v1]. Итоговый экономический эффект равен разнице между потерями до внедрения модели и после.2. Оптимизация доли одобренных заявок (Approval Rate Optimization)Суть: Метрика показывает способность модели удерживать баланс между объемом выдаваемых кредитов (прибыль банка) и уровнем риска.Как рассчитать на основе выходов модели:Модель относит клиента к категории надежных (verdict = Approve), если его персональная вероятность дефолта ниже установленного банком порога отсечения (Threshold) [v1].\(\text{Approval\ Rate}=\frac{\text{Количество\ клиентов\ с\ }verdict=Approve}{\text{Общее\ количество\ заявок}}\)Динамически сдвигая порог отсечения (например, одобрять только тех, у кого вероятность дефолта менее 15%), банк может гибко увеличивать долю одобренных заявок в периоды экономического роста или жестко снижать ее в периоды кризиса, удерживая средний кредитный риск портфеля на фиксированном уровне.
